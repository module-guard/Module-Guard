# 신뢰 그래프 검증 (#50)

`graph-quality.spec.ts`는 계보, 버전 비교, 정적 위험 경로, 동적 비실행 데모를 검증한다. 기존 그래프·페이지 로딩을 그대로 사용하며 API/DB를 변경하지 않는다. 모든 API GET을 fixture로 가로채고 예상하지 않은 요청이나 변경 요청은 실패시킨다. 실제 Terraform 실행이나 실사용자 데이터는 없다.

## 측정 행렬

| 화면          | 20 / 200 / 1,000의 의미         | 현재 한 화면에 로드하는 데이터                                                        |
| ------------- | ------------------------------- | ------------------------------------------------------------------------------------- |
| 계보          | 파생 계보 총수 (중심 원본 별도) | 기존 20개 페이지 + 중심 1개. 다음 페이지 요청 확인                                    |
| 버전 비교     | 리소스 변경 총수                | 기존 50개 페이지. 다음 페이지 요청 확인                                               |
| 위험 경로     | finding 총수                    | 기존 20개 페이지. 선택 경로는 20 / 200 / 201노드, 최대 200edge. 다음 페이지 요청 확인 |
| 동적 타임라인 | 합성 단계·이벤트·리소스 노드 수 | 기존 단계 표시 상한 100개, 그래프는 20 / 200 / 1,000노드와 N-1개 edge 유지            |

계보·비교의 페이징을 해제해 전체 1,000개를 한 번에 그리는 실험은 하지 않는다. 위험 경로 fixture도 실제 경로당 200edge 상한을 따른다. 동적 데모는 기존 `backend/app/dynamic/fixtures/success.json`을 확장한 4분기 트리다. 그래프 노드 찾기의 option 수로 로드된 노드가 누락되지 않는지 별도로 확인하며, 렌더링된 DOM 노드 수와 단계 수를 기록한다. fixture는 페이지만 생성해 테스트 자체의 과도한 메모리 사용을 피한다.

## 방법과 한계

- 프로덕션 Next 빌드, 1280×900, Chromium 계열 브라우저, worker 1개, CPU/네트워크 인위적 감속 없음. 각 테스트는 새 브라우저 context를 쓴다.
- 첫 표시: 개요/검사 화면 로딩 완료 후 신뢰 탭 또는 위험/동적 상세를 여는 동작부터 첫 그래프 노드 표시·배치 대기 종료·두 번의 animation frame까지. 계보는 파생 방향 선택까지 포함한다. **전체 페이지의 cold load, FCP/LCP, 서버 처리 시간은 아니다.** 신뢰 탭의 다른 동시 요청 비용은 포함한다.
- 선택→상세: 대체 목록의 두 항목을 번갈아 5회 선택한다. 올바른 근거가 표시되고 두 frame이 지난 시간 중 최댓값을 쓴다. 비교의 이미 열린 details는 닫은 뒤 다시 연다. Playwright의 auto-wait와 스크롤 비용을 포함하는 사용자 흐름 측정이며 INP나 통계적 p95가 아니다.
- 레이아웃 이동: 진입 동작 직전 초기화한 `PerformanceObserver(layout-shift)` 합계. `hadRecentInput`은 제외한다. 의도적인 details 열림·사용자 스크롤·그래프 내부 좌표 변경 전체를 수치화한 것은 아니다.
- 장시간 작업: 같은 구간의 `PerformanceObserver(longtask)` 최장/누적 시간. 별도의 100ms timer 작업으로 측정기가 실제 지연을 감지하는지 교정한다. 지원되지 않거나 관측하지 못하면 교정 테스트가 실패한다.
- 메모리: CDP `HeapProfiler.collectGarbage` 후 `Runtime.getHeapUsage.usedSize`를 선택 전/후 측정한 **main renderer JS heap**이다. 5회 선택 뒤 사용량과 증가량을 검사한다. worker heap, GPU, DOM/native 메모리, 전체 RSS·최고 사용량은 포함하지 않는다. 음수 증가는 GC 차이이며 장시간 누수 없음의 증명이 아니다.
- 시간·heap 수치는 환경에 민감하다. 실측은 M4/macOS이며 Ubuntu CI의 수치로 오인하지 않는다. 이 기준선은 실제 네트워크 지연이나 모든 그래프 토폴로지를 대표하지 않는다.

### 발견하여 수정한 결함

- 조작 버튼을 포함하는 그래프를 `role=img`로 묶어 발생한 `nested-interactive`: 공용 wrapper를 이름 있는 `group`으로 변경. 기존 platform E2E의 동일 그래프 role 조회도 함께 수정했다. 기능·개수 기대값은 유지한다.
- 이름을 가질 수 없는 범례 div의 `aria-prohibited-attr`: 이름 있는 `group` 역할 부여.
- 작은 안내·유형·근거 선택 버튼의 `color-contrast`: 공용 유형 palette와 보조 글자, 해당 화면 링크 색을 어둡게 조정. 범례/유형 텍스트는 유지한다.
- 위험 경로 375px에서 section 309px 대비 내용 379px 가로 넘침: 공용 toolbar label/select의 최소 폭과 줄 배치 수정. 수정 후 309/309px. 내용 숨김으로 통과시키지 않는다.
- 동적 근거 선택마다 동일 그래프를 새 배열로 전달해 1,000노드 worker 배치가 재시작됨: run 데이터 기준 memo 사용. 기존 버전에서 재시작 1회로 실패하는 회귀 테스트가 수정 후 0회로 통과했다.

## 실행과 CI

```sh
npm ci
npx playwright install chromium
# 기존 격리 API/DB와 프로덕션 프런트를 시작하는 저장소 표준 설정
npm run test:e2e -- e2e/graph-quality.spec.ts --reporter=list,html
# 동일 환경에서 3회 재측정 (예산 계속 검사)
npm run test:e2e -- e2e/graph-quality.spec.ts --grep 'graph performance:' --repeat-each=3
```

이미 프로덕션 프런트가 실행 중이면 `PLAYWRIGHT_BASE_URL=http://localhost:3100`을 설정해 서버·DB 재시작 없이 실행할 수 있다. 이 suite 자체는 모든 API를 mock하므로 실제 backend가 필요 없다. 개발 서버의 첫 컴파일 시간과 섞지 않는다.

기존 `.github/workflows/ci.yml`의 `npx playwright test`가 이 파일을 자동 수집하므로 별도 workflow는 추가하지 않았다(#49와 충돌 방지). 로컬에서 추가 suite 22개 **39.0초**, 성능만 3회/36개 **54.9초**였다. CI는 기본 22개만 실행한다. Ubuntu runner의 추가 소요 시간은 아직 측정하지 않았으며 기존 45분 job 제한은 바꾸지 않는다.

각 성능 테스트는 `GRAPH_QUALITY` 로그와 `graph-performance.json`, 접근성 테스트는 `GRAPH_AXE` 로그와 `axe.json`·화면 이미지를 남긴다. 기존 CI는 실패 시 `test-results/`, HTML report, trace를 artifact로 올린다. 성공 시 수치는 job 로그에서 볼 수 있다. 운영 데이터·로그 원문은 수집하지 않는다.
